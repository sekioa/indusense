## Complément du support AELION

Les diapositives ci-dessous complètent les schémas, formules et extraits de code qui ne sont pas tous lisibles dans l'audio. Elles ne modifient pas la transcription horodatée ci-dessus.

### Évaluer sur un jeu de test

- Le **test set** (jeu de test) représente typiquement 20 % à 30 % des données et doit être représentatif des données de production. Il sert à tester la fiabilité du modèle après son entraînement.
- La démonstration du support entraîne le modèle sur `X_train, y_train`, prédit `y_pred = model.predict(X_test)`, puis compare `y_test` et `y_pred`, par exemple avec `metrics.accuracy_score(y_test, y_pred)` de scikit-learn.
- Pour des observations indépendantes et identiquement distribuées, un découpage aléatoire peut être approprié. Pour des données temporelles, l'ordre chronologique doit être conservé : il ne faut pas appliquer ce tirage aléatoire au cas de maintenance prédictive vu dans le TP.

### Régression

Pour chaque observation, l'erreur est `y_pred - y_test`. Le support illustre ensuite deux transformations avant de calculer une moyenne :

- **MAE** (*Mean Absolute Error*) : moyenne des erreurs absolues. Exemples : `-2`, `-3`, `+10` deviennent `2`, `3`, `10`.
- **MSE** (*Mean Squared Error*) : moyenne des erreurs au carré. Ces mêmes erreurs deviennent `4`, `9`, `100` ; une forte erreur pèse donc davantage.
- **R² score** : comparaison avec un modèle constant qui prédit toujours la moyenne de `y_train` :

  `R² = 1 - MSE_notre_modele / MSE_modele_constant`

  Un R² proche de 1 indique une erreur bien plus faible que celle de ce modèle de référence ; R² = 0 indique une performance équivalente ; R² peut être négatif sur le jeu de test.

### Classification binaire

Le support note `A` la classe positive et `B` la classe négative. Une prédiction correcte a une erreur nulle ; une erreur de classe a une erreur égale à 1. L'**accuracy** est le pourcentage de prédictions correctes, mais elle ne suffit pas lorsque la classe positive est rare.

| Réalité / prédiction | Prédite négative | Prédite positive |
| --- | --- | --- |
| Réellement négative | TN (*true negative*) | FP (*false positive*) |
| Réellement positive | FN (*false negative*) | TP (*true positive*) |

- **Recall** (rappel) : `TP / (TP + FN)`. Parmi les positifs réels, il mesure ceux détectés.
- **Precision** (précision) : `TP / (TP + FP)`. Parmi les positifs prédits, il mesure ceux qui sont réellement positifs.
- **F1** est la moyenne harmonique de precision et recall : `2 × precision × recall / (precision + recall)`.

### ROC-AUC et seuil de décision

Le modèle attribue à une observation `x` un score `p(x)`, interprété dans le support comme une probabilité d'appartenir à la classe positive. Une prédiction dépend d'un **seuil de décision** : au-dessus du seuil, la classe positive est prédite ; au-dessous, la classe négative l'est. Déplacer ce seuil modifie le compromis entre faux positifs et faux négatifs.

La courbe **ROC** représente le taux de vrais positifs (TPR, identique au recall) en fonction du taux de faux positifs (FPR) pour l'ensemble des seuils. Son **AUC** est l'aire sous la courbe : elle peut aussi se lire comme la probabilité qu'un positif reçoive un score supérieur à un négatif. Une AUC proche de 1 correspond à une bonne séparation des classes ; une AUC proche de 0,5 correspond à un classement aléatoire.
